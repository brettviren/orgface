#+title: orgface
#+options: toc:2

Do some Emacs org things quickly from the command line.

Copyright (C) 2026 Brett Viren <brett.viren@gmail.com>. Free software under
the GNU GPL version 3 or later; see [[#licence][Licence]].

The CLI is shaped like =git=: a top level program with subcommands that do
one thing and exit. It manages an =emacs --daemon= the way =ssh= manages a
master control connection — started on first use, reused by later commands,
and shut down by itself once it has been idle long enough.

The entry point is =orgface=. This document assumes you have aliased
it to =org=:

#+begin_src sh
alias org=orgface
#+end_src

* Quick start

#+begin_src sh
org commit -m "Fixed the thing" -m "Took all day."
org note -m "Fixed the thing" -m "Took all day."
org log --today
org log --since "2 weeks ago" --oneline
org visit yesterday
org daemon status
#+end_src

* Documentation

This file is the tour. The reference is a wiki of org files in [[file:docs/org/][docs/org/]],
one concept to a page: start at [[file:docs/org/index.org][docs/org/index.org]], or go straight to the
[[file:docs/org/user-guide.org][user guide]] or the [[file:docs/org/developer-guide.org][developer guide]].

Those pages are themselves a store, so the documentation can be read with
the tool it documents:

#+begin_src sh
export ORGFACE_STORE_BACKEND=orgfs
export ORGFACE_STORE_DIRECTORY=docs/org
org store list
org store show node-refs.org
#+end_src

* Installation

orgface uses [[https://docs.astral.sh/uv/][uv]] for development.

#+begin_src sh
uv sync                # set up the development area
uv run pytest          # run the tests
uv run orgface  # run the CLI
#+end_src

Emacs must provide =org-roam=. Nothing about your notes or your Emacs
configuration is duplicated here: the capture templates and the org-roam
directories are read from the running daemon, which loads your normal init
file.

* The daemon

Commands that need Emacs talk to a daemon under a private server name,
=orgface= by default, so your interactive Emacs is never touched. If
you would rather share one Emacs, point =daemon.server_name= at it.

- The first command needing Emacs starts the daemon. Cold start costs a few
  seconds; everything afterwards is a few tens of milliseconds.
- Every request resets an idle timer inside Emacs. After
  =daemon.lifetime= of quiet the daemon saves modified buffers and exits.
  The default is one hour; =never= keeps it alive indefinitely.
- No supervising process is involved. The countdown lives in the daemon,
  so nothing is left behind if the CLI is interrupted.

=org daemon= exposes =start=, =stop=, =restart=, =status= and =info= for
when you want to take charge explicitly.

* Commands
** org commit

Record an entry in today's org-roam daily note, in the style of
=git commit=. The first =-m= is the entry title; any further =-m= options
become body paragraphs.

#+begin_src sh
org commit -m "Fixed the thing" -m "Took all day." -m "Worth it."
#+end_src

With no =-m= at all, an interactive capture opens in the terminal, exactly
as =org-roam-dailies-capture-today= would. Finishing or aborting the
capture returns you to the shell. Use =--gui= for a separate frame instead.

*** Choosing a template

Writing goes through =org-roam-dailies-capture-today=, so the templates on
offer are the ones in your =org-roam-dailies-capture-templates=. Note this
is a different variable from =org-roam-capture-templates=: if you want a
directory-based daily note, add that template to the *dailies* list.

=-t/--template= selects one by *key*, then by *0-based index*, then by
*description*, in that order of precedence — so a template keyed =1= still
wins over the template at index 1. Descriptions match case-insensitively
and may be abbreviated to an unambiguous prefix. Without =-t= the first
template is used. If you define no templates at all, org-roam's own
default applies.

#+begin_src sh
org commit --list-templates      # what is on offer
org commit -t d       -m "..."   # by key
org commit -t 0       -m "..."   # by index
org commit -t default -m "..."   # by description
#+end_src

*** Seeing what would be written

=--dry-run= prints the capture text that would be handed to Emacs and
writes nothing:

#+begin_src sh
$ org commit --dry-run -m "Fixed the thing" -m "Took all day."
* Fixed the thing
%T
%?Took all day.
#+end_src

The =%T= and =%?= are still there because Emacs, not this tool, expands
them. Your message text is escaped so that it cannot be.

** org note

Record an entry the way =org commit= does, but keep the context it was
written in and file it under a topic rather than under today's date.

#+begin_src sh
org note -m "Fixed the thing" -m "Took all day."
#+end_src

The first =-m= is the title and any further =-m= options become body
paragraphs, exactly as for =commit=. With no =-m= an interactive capture
opens with the context already in place and Emacs asking you for the title;
=--gui= puts it in a frame of its own.

*** The context

Where and when the command ran becomes part of the entry: an inactive org
timestamp to the second, and the working directory, host and user as
properties on the headline. Inactive, because a record of when something was
written is not something to be done and has no business in your agenda.

#+begin_src org
* Fixed the thing :home:orgface:
:PROPERTIES:
:DIRECTORY: /home/you/dev/orgface
:HOST: yourhost
:USER: you
:END:
[2026-08-04 Tue 13:45:02]

Took all day.
#+end_src

The headline tags say where that was:

- =home= when the working directory is your =$HOME=.
- The name of the enclosing git working tree, if the working directory or
  any directory above it holds a =.git=. A =.git= file counts as well as a
  directory, so worktrees and submodules are tagged too.

Org accepts only alphanumerics and =_@#= in a tag, so a repository named
=orgface= is tagged =orgface=: runs of anything else collapse
to a single underscore, and a name with nothing usable left in it is not
tagged at all.

*** The topic

Entries go to an org-roam topic, by default one titled =Context Notes=,
which is created on first use like any other org-roam node. =-T/--topic=
names a different one, and =note.topic= changes the default:

#+begin_src sh
org note -T "Work Log" -m "Fixed the thing"
#+end_src

Because the topic is looked up by title, the note joins whatever node
already carries that title; only when there is none is a new file made, in
your =org-roam-directory= and in the same form org-roam itself would use.

=--dry-run= prints what would be handed to Emacs, and =-q/--quiet= suppresses
the summary. Unlike =commit= the capture template is built by this tool, so
=org-roam-dailies-capture-templates= and =-t= play no part.

Notes live outside the dailies, so =org log= does not report them; read a
topic with =org visit -T= instead. The entry is shaped like a daily entry
all the same — heading, properties, timestamp, then the text — so nothing
about it is peculiar to this tool.

** org log

Show recent daily entries, newest first, through your pager. Each top level
heading in a daily note is one entry — the unit =org commit= creates —
which makes it the natural analogue of a commit.

Daily notes are read straight from disk, so =org log= works whether or not
Emacs is running.

| Option              | Meaning                                        |
|---------------------+------------------------------------------------|
| =--today=           | Only entries written today                     |
| =--since=, =--after=  | At or after a date                             |
| =--until=, =--before= | At or before a date                            |
| =-n=, =--max-count=   | Limit to the N most recent entries             |
| =--oneline=         | One compact line per entry                     |
| =--reverse=         | Oldest first                                   |
| =--color=           | =auto= (default), =always=, =never=                |
| =--no-pager=        | Write straight to stdout                       |
| =--refresh=         | Re-read org-roam locations from Emacs          |

Dates accept =YYYY-MM-DD= (also =YYYY/MM/DD=, =YYYYMMDD=, and with a time),
=today=, =yesterday=, =now=, and the =N units ago= family including git's
dotted spelling — =2.weeks.ago=, =3 days ago=, =last month=. This is a
documented subset of git's =approxidate=, not a reimplementation of it;
anything unrecognised is reported rather than guessed at.

An upper bound named as a bare day covers that whole day, so
=--until 2026-07-30= includes everything written on the 30th.

** org visit

Open a note in Emacs, in a frame of its own, without waiting for you to
close it.

#+begin_src sh
org visit                     # today's daily note
org visit yesterday           # a daily note by date
org visit 3 days ago          # dates need no quoting
org visit -T                   # the topic 'note' captures into
org visit -T "Work Log"        # a topic by title
#+end_src

Without =-T= the arguments are a date, in the same free-form spelling
=org log= takes. With =-T= they are an org-roam topic title instead, taken
as =note -T= takes it, and default to =note.topic=. Either way, a note that
does not exist is reported rather than created.

Finding a topic means asking org-roam's database, so =visit -T= needs the
daemon. Visiting a daily note does not.

** org config

=org config show= prints the resolved configuration, as loadable TOML, and
where it came from, =org config init= creates a default config file if none
exists, =org config paths= the XDG locations in use, and =org config clear-cache=
forgets the cached org-roam locations.

** org store

The store keeps org documents in a canonical, schema-validated JSON form
so they can be queried and edited a piece at a time. It is independent of
the capture commands above and needs no Emacs daemon.

#+begin_src sh
org store add notes.org                     # add an org file (no Emacs needed)
org store add exported.json --id notes.org  # or canonical JSON from ox-json
org store add a.org b.org c.org            # several at once, in order
org store add notes.org --id notes.org  # name it yourself, not by its full path
org store list                              # one line per document
org store show notes.org                    # summary
org store show notes.org --json             # the canonical document
org store node notes.org org1a2b3c4d5e6f    # one node, addressed by ref
org store rm-node notes.org org1a2b3c4d5e6f
org store rm notes.org
org store reindex                           # rebuild the derived tables
#+end_src

Org files are read by a standalone tree-sitter parser, so nothing here
needs Emacs running. Canonical JSON — the shape [[https://github.com/jlumpe/ox-json][ox-json]] exports — is accepted
too, and both land on the same document.

*Refs name positions, not objects.* A ref is a hash of the document id and
the node's structural path, recomputed on this side rather than taken from
whichever parser produced the document, so both ingestion paths agree.
The consequence is that inserting or deleting a node changes the refs of
its later siblings: re-read a document before reusing a ref taken before
an edit. The identifier that survives edits is the one org already has,
the =ID= property.

*The JSON is the source of truth.* Everything else in the database —
nodes, tags, properties, links, timestamps — is an index derived from it
on every write. =org store reindex= rebuilds all of it from the stored
documents, so a change to how content is indexed needs no migration.

The schema is generated from the model and committed at
=src/org_store/schemas/org-document.schema.json=. Regenerate it with
=uv run python -m org_store.schema=; a test fails if it drifts.

** org search

Full text search over everything in the store, down to the individual
node rather than the whole file.

#+begin_src sh
org search inline math                    # both words, anywhere
org search 'E=mc^2'                       # punctuation is text, not syntax
org search neutr*                         # prefix match
org search deadline --scope heading       # headings only
org search --scope body notes             # bodies only
org search dune -t physics                # only under headings tagged :physics:
org search setup -T src-block             # only source blocks
org search plan -p CATEGORY=work          # only under headings with that property
org search plan -d notes.org -n 5         # one document, at most five hits
#+end_src

Words are ANDed, so two words means both. A trailing =*= matches by
prefix; everything else is taken literally, so maths and punctuation need
no quoting.

*Tag and property filters are inherited*, the way org inherits them: a
paragraph under a heading tagged =:urgent:= is part of something urgent
and will be found by =-t urgent=, even though only the heading carries
the tag.

*A hit names a node, not a file.* Each result prints =DOC_ID:REF=, which
=org store node= takes directly. Matching against headings and bodies
separately is what makes =--scope= meaningful — a heading match ranks
above a passing mention in prose.

Search is available for whichever store the content lives in; a backend
that keeps no index says so rather than quietly returning nothing.

*** Searching by meaning

=-s/--semantic= matches on meaning rather than words, using embeddings:

#+begin_src sh
org store embed              # build them; only changed text is sent
org store embed --status     # how much of the store is covered
org search -s "physics equations"
#+end_src

Word search finds nothing for "physics equations" in a note that says
=\begin{equation} \nabla \cdot \mathbf{E}=...= — semantic search finds
it. The same =-t=, =-T=, =-p= and =-d= qualifiers apply. =--scope= does
not: a vector is of the whole node, not of its heading or its body.
Each hit is led by its cosine similarity to the query, from 1 down.

This needs an embedding model. The default expects [[https://github.com/ggml-org/llama.cpp][llama.cpp]]'s
=llama-server= on =127.0.0.1:8080= serving nomic-embed-text, and the
=semantic= extra for the vector index:

#+begin_src sh
llama-server -m ~/models/nomic-embed-text-v1.5.Q8_0.gguf --embeddings
uv sync --extra semantic     # or: pip install 'orgface[semantic]'
#+end_src

Passages and questions are embedded differently — nomic-embed-text is
trained that way, and treating them alike measurably worsens retrieval —
so that is a difference in the interface rather than a flag to forget.

*Embedding is a separate step from writing, on purpose.* It costs a call
to a model that may not be running, and storing a document should not
fail for that reason. So =org store embed= is asked for, and it is
incremental: a node whose text has not changed is not sent again.
Changing =embed.model= invalidates every vector the old one produced,
because vectors from two models do not live in the same space.

** Store backends

Three, chosen with =store.backend=. All answer the same commands.

- =sqlite= (the default) keeps documents in one database with the derived
  indexes that make =org search= possible. Nothing but this tool reads it.
- =orgfs= keeps them as ordinary org files in a directory. There is no
  database and nothing to import: a file you wrote by hand is already in
  the store, and Emacs, git and your editor are all first-class writers.
  It has no search index, and says so rather than returning nothing.
- =emacs= reads that same directory through your running Emacs, using
  [[https://github.com/jlumpe/ox-json][ox-json]]. Slower, and it needs =ox-json= installed, but it is the only
  reader that is *definitionally* right: org-element decides what org
  means, and it is running inside your configuration — your link types,
  your TODO keywords, your in-buffer settings. It also sees a buffer's
  unsaved edits, which nothing reading the file can.

The =orgfs= backend needs the parser and renderer, which are an optional
extra so that sqlite-only users need not install them:

#+begin_src sh
uv sync --extra orgfs        # or: pip install 'orgface[orgfs]'
#+end_src

*Writing re-renders the whole file.* Everything the model records survives
— a round trip is checked in the test suite against the whole fixture
corpus and is exact — but formatting the model does not record does not:
blank-line runs and table column alignment come back normalised, the way
org itself normalises them on save. Rendering is idempotent, so a file
settles after the first write rather than drifting on each one.

*A document's content hash is the same in every backend.* It is taken
over the document rendered back to org text — not over its JSON, and not
over the bytes of any file it came from. That is what makes it portable:
ox-json carries org-element's own bookkeeping (=mode=, =true-level=, a
=post-blank= on everything) that no independent parser can reproduce, so
the two readers never agree on JSON. They do agree on the org text, which
is what the document actually says.

Hashing the rendering rather than the file also normalises formatting the
model does not record, so a hand-aligned table and a freshly written one
hash alike — as they should, since they say the same thing.

*The =emacs= backend will not overwrite unsaved work.* It is one writer
among several, and the others include you with the file open. If Emacs
has unsaved changes to a file, writing to it or deleting it is refused
rather than resolved — a merge invented here would be a worse answer
than a clear stop. An unmodified buffer is written under and then
reverted, so Emacs is never left showing content the file no longer has.

** org store sync

Copy documents from one store to another. The commonest use is keeping a
sqlite store, for its search, alongside the org files you actually edit.

#+begin_src sh
org store sync orgfs:~/org              # configured store -> those files
org store sync orgfs:~/org --pull       # those files -> configured store
org store sync orgfs:~/org --dry-run    # say what would change
org store sync orgfs:~/org --prune      # also delete what the source lacks
org store sync sqlite                   # that backend's usual location
#+end_src

Only documents whose content actually differs are written, so a second
run reports everything unchanged. That works across backends because a
content hash means the same thing in all of them.

*This is a copy, not a merge, and the source always wins.* Comparing two
stores tells you a document differs — not which side changed it. So an
edit made at the destination is overwritten, and no amount of care here
could avoid that: knowing who changed what needs a record of the last
sync and a three-way merge, and neither exists yet. Run =--dry-run= first
when it matters. The one-line summary always names the direction.

A document that cannot be read is reported and the run carries on, so one
unreadable file does not leave the rest half-copied. The command exits
non-zero if anything failed.

** org render

Write documents from the store out as some other kind of text.

#+begin_src sh
org render notes.org                # -> notes.html
org render notes.org -o -           # -> standard output
org render -a -o site/              # every document -> site/*.html
org render notes.org -m emacs       # org-export, inside Emacs
org render notes.org -t mine.j2     # a template of your own
#+end_src

Name the documents, or pass =-a/--all= for all of them; with neither, the
command prints its help rather than guessing. A name that leaves off
=.org= still finds the document, and a name that matches nothing is
reported before anything is written.

*Where the text goes follows from what was asked for.* One named document
goes to the file =-o= names, to =-= for standard output, or to its own
name in the current directory. Several, or =-a=, go to the directory =-o=
names, or to =output/=, keeping whatever subdirectory layout the store
has. An =-o=
that is already a directory holds the file; anything contradictory — many
documents down =-o -=, or into an existing file — is refused.

*Two methods, chosen with =-m/--method=.*

- =template= (the default) applies a Jinja2 template to the document's
  canonical JSON. It needs no Emacs, and a different rendering is a
  template rather than a patch. =-t/--template= names your own.
- =emacs= runs org-export in the daemon, so the exporter is org's own,
  with your backends, filters and in-buffer settings. A document that is
  already a file is exported where it lies, so relative links and
  includes resolve as they would for you.

=-f/--format= says what is being produced — =html= to begin with. It
picks the packaged template, the org-export backend, and the file
extension. Adding a format is an entry in =org_store.export.FORMATS= and
a template beside it.

Links between org files become links between renderings, so a wiki
rendered whole is browsable:

#+begin_src sh
org render -a -o site/ && xdg-open site/index.html
#+end_src

** org serve and org mcp

The same operations again, over HTTP and as [[https://modelcontextprotocol.io][MCP]] tools, so that an agent or
another program can use the store without shelling out.

#+begin_src sh
uv sync --extra service      # or: pip install 'orgface[service]'

org serve                    # http://127.0.0.1:8765
org serve --schema           # print the OpenAPI document, serve nothing
org mcp                      # speak MCP on stdin/stdout
org mcp --list-tools         # what an agent would see
#+end_src

*The MCP tools are generated from the HTTP API*, not written a second
time: each tool's name, arguments and result come from the operation's
OpenAPI description, so adding a route adds a tool and the two cannot
drift apart. The MCP server calls the API in process, over an ASGI
transport — no socket, no port, nothing else can reach it.

Point an MCP client at the =org mcp= command:

#+begin_src json
{"command": "orgface", "args": ["mcp"]}
#+end_src

Twelve tools come out: =list_documents=, =read_document=,
=read_document_text=, =summarise_document=, =create_document=,
=replace_document=, =delete_document=, =read_node=, =update_node=,
=delete_node=, =search= and =embed=.

=org serve= binds to localhost and has *no authentication*. It is for
local tools; it is not something to expose to a network.

* Configuration

orgface follows the freedesktop XDG conventions. Configuration is
read from a file named with =-c/--config=, otherwise from
=~/.config/orgface/config.toml=. Cached org-roam locations live
under =~/.cache/orgface/=.

Layers apply in last-one-wins order:

: environment variables -> config file -> command line options

#+begin_src conf-toml
[daemon]
server_name   = "orgface"  # ORGFACE_SERVER_NAME
lifetime      = "1h"              # ORGFACE_LIFETIME
emacs         = "emacs"           # ORGFACE_EMACS
emacsclient   = "emacsclient"     # ORGFACE_EMACSCLIENT
start_timeout = "120s"            # ORGFACE_START_TIMEOUT

[roam]
# Both are discovered from the daemon and cached when left unset.
directory         = "~/org/roam"  # ORGFACE_ROAM_DIRECTORY
dailies_directory = "daily/"      # ORGFACE_DAILIES_DIRECTORY

[note]
topic = "Context Notes"           # ORGFACE_NOTE_TOPIC

[log]
pager = "less"                    # ORGFACE_PAGER

[embed]
url        = "http://127.0.0.1:8080"   # ORGFACE_EMBED_URL
model      = "nomic-embed-text-v1.5"   # ORGFACE_EMBED_MODEL
dimensions = 768                       # ORGFACE_EMBED_DIMENSIONS
# api_key  = "..."                     # ORGFACE_EMBED_API_KEY; prefer the env var
# api_key_passname = "embed/key"       # ORGFACE_EMBED_API_KEY_PASSNAME; first line of `pass embed/key`

[store]
backend   = "sqlite"       # ORGFACE_STORE_BACKEND: sqlite or orgfs
database  = "~/.local/state/orgface/store.sqlite"
                           # ORGFACE_STORE_DATABASE, for sqlite
directory = "~/org"        # ORGFACE_STORE_DIRECTORY, for orgfs
#+end_src

Durations accept =90s=, =30m=, =1h=, =1h30m=, =2 hours=, =1d=, a bare
number of seconds, or =never= (equivalently =none=, =inf=, =0=) to disable
expiry.

Setting =roam.directory= and =roam.dailies_directory= explicitly lets
=org log= run without ever consulting Emacs.

* Notes and limitations

*Your message text is never expanded.* Splicing text into a capture
template means Emacs would otherwise interpret =%t=, =%(sexp)=, =%^{...}=
and friends in whatever you wrote — =%(shell)= would genuinely start a
shell. Messages are escaped so every such sequence survives literally. The
escaping accounts for org-roam expanding a capture body *twice*, which is
why =tests/test_emacs_live.py= checks it against a real Emacs rather than
trusting the arithmetic.

*=${...}= is refused.* org-roam expands =${foo}= by calling a function
named =foo= or prompting for a value, and offers no escape mechanism at
all. Rather than execute or hang, =org commit -m= refuses such a message
and says so. Capture interactively if you need that text. =org note=
refuses it in the context too, on the vanishing chance of a working
directory named that way.

*=%?= in a title is reported.* Emacs finds the capture point with a plain
search for =%?= that honours no escaping. A =%?= in the body is safe, but
one ahead of the capture point cannot be protected, so a warning is
printed instead of pretending otherwise.

*Whitespace follows your template literally.* The body is placed exactly
where =%?= sits. With the common =* %^{Title}\n%T\n%?= there is no blank
line between the timestamp and the body. If you would rather have one, put
it in the template:

#+begin_src elisp
(setq org-roam-dailies-capture-templates
      '(("d" "default" entry "* %^{Title}\n%T\n\n%?"
         :target (file+head "%<%Y-%m-%d>.org" "#+title: %<%Y-%m-%d>\n"))))
#+end_src

*Templates needing a person are refused for =-m=.* Interactive escapes
with no non-interactive answer (=%^t=, =%^{Prop}p= and similar) cause
=commit -m= to stop and suggest capturing interactively. A second plain
=%^{...}= prompt is filled empty with a warning, since the first one takes
the title.

* Development

Tests live in =tests/= and run with =uv run pytest=.

#+begin_src sh
uv run pytest                  # everything
uv run pytest -m "not emacs"   # skip the live Emacs integration tests
#+end_src

The =emacs=-marked tests build a throwaway org-roam directory and an init
file of their own, then drive a real daemon against them, so your notes and
your Emacs configuration are untouched. They skip when Emacs or org-roam
cannot be found.

Every source file carries an [[https://spdx.dev/][SPDX]] header naming the
copyright holder and the licence, so the notice stays machine readable
without a paragraph of boilerplate per file.

Layering follows =CLAUDE.md=: =cli.py= and =commands/= parse and present,
=ui.py= renders, and the decisions live in the data modules —
=config.py=, =templates.py=, =context.py=, =dailies.py=, =dates.py=,
=locations.py=, =emacs.py= and =elisp.py=. =bootstrap.el= is the daemon-side half, loaded
on demand and returning base64 JSON so nothing has to parse Emacs' printed
output.
