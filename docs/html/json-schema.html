The JSON schema

reference developer store

The pydantic model is the definition. The schema is that model rendered as JSON Schema, so consumers which are not Python — the Emacs side, an MCP client, anything reading the stored JSON directly — have something to validate against.

It is committed at src/org_store/schemas/org-document.schema.json and regenerated with: 

uv run python -m org_store.schema

A test asserts the committed copy still matches the model, so a change that alters the stored shape shows up as a schema diff to review rather than as a silent change nobody noticed.

Validation mode, not serialisation mode

The schema is generated in validation mode on purpose. It is the contract for "is this a conforming org document", which has to accept what ox-json emits — not merely what this code produces when it dumps a document.

Versioning

SCHEMA_VERSION lives on the model and is bumped whenever a change alters the stored JSON shape. Every document carries the version it was written under, and the $id of the schema names it, so a stored document can always say which contract it was written against.
