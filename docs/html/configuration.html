Configuration

concept reference user config

Every setting is declared once, in SETTINGS in config.py, with its attribute name, its TOML section and key, its environment variable, its default, and how to coerce it. Each layer reads that one declaration, so a new setting is one entry rather than four edits.

Layers

Layers apply in last-one-wins order: 

environment variables -> config file -> command line options

That the file beats the environment is deliberate: the file is the considered choice and the environment is the ambient one. A command line option beats both, and an option left unset does not count as a value, so it cannot clobber a lower layer with None.

The file is named with -c/--config, or found at ~/.config/orgface/config.toml — see XDG locations.

The settings

[daemon]
server_name   = "orgface"  # ORGFACE_SERVER_NAME
lifetime      = "1h"              # ORGFACE_LIFETIME
emacs         = "emacs"           # ORGFACE_EMACS
emacsclient   = "emacsclient"     # ORGFACE_EMACSCLIENT
start_timeout = "120s"            # ORGFACE_START_TIMEOUT

[roam]
directory         = "~/org/roam"  # ORGFACE_ROAM_DIRECTORY
dailies_directory = "daily/"      # ORGFACE_DAILIES_DIRECTORY

[note]
topic = "Context Notes"           # ORGFACE_NOTE_TOPIC

[log]
pager = "less"                    # ORGFACE_PAGER

[embed]
url        = "http://127.0.0.1:8080"   # ORGFACE_EMBED_URL
model      = "nomic-embed-text-v1.5"   # ORGFACE_EMBED_MODEL
dimensions = 768                       # ORGFACE_EMBED_DIMENSIONS

[store]
backend   = "sqlite"       # ORGFACE_STORE_BACKEND
database  = "~/.local/state/orgface/store.sqlite"
directory = "~/org"        # for the orgfs and emacs backends

An unknown section or key in the file is reported by name rather than ignored, on the grounds that a typo in a config file is a question, not a preference.

Value spellings

Durations
=90s=, 30m, 1h, 1h30m, 2 hours, 1d, a bare number of seconds, or never (none, inf, 0) to disable expiry.
Paths
=~= and =$VARIABLES= are expanded.
Booleans
=1/true/yes/on= and 0/false/no/off.

Seeing what is in effect

org config show prints the resolved value of every setting, its dotted key, its environment variable, and which file it came from — the fastest way to find out why a command is using a store you did not expect. See org config.
