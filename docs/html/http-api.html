The HTTP API

reference developer service

The store as a FastAPI application. This is one definition serving two purposes: describing the operations once, with typed requests and responses, gives an OpenAPI document for free — and the MCP server is derived from that document rather than hand-written.

Every handler is a single call into the service layer. Nothing here decides anything, which is the same rule the CLI follows and what lets a third adapter be added without a fourth copy of the logic.

The operations

MethodPathOperation id
GET/documentslist_documents
POST/documentscreate_document
GET/documents/{id}read_document
PUT/documents/{id}replace_document
DELETE/documents/{id}delete_document
GET/documents/{id}/summarysummarise_document
GET/documents/{id}/textread_document_text
GET/documents/{id}/nodes/{ref}read_node
PUT/documents/{id}/nodes/{ref}update_node
DELETE/documents/{id}/nodes/{ref}delete_node
POST/searchsearch
POST/embedembed

read_document_text returns the document as org text, which is what a person would read; read_document returns the canonical JSON, which is what a program should.

update_node returns the ref the node has after the edit, because refs name positions and the one sent may no longer name anything.

Failures carry meaning

A store error becomes the status code that means it: 404 for a document or node that is not there, 409 for an id that already exists, 400 for anything else, each with the store's own message as the detail.

No configuration in here

The store is opened per request through a callable given at construction, so this module knows nothing about configuration — which is what keeps org_store free of any dependency on the CLI that configures it.
