Glossary

reference user developer

Document
one org file's worth of content, in the canonical form. What org store creates, reads and deletes.
Document id
how a store names a document, opaque above the backend that issued it. A file store uses a path relative to its root.
Node
one element inside a document — a heading, a paragraph, a source block, a link, a timestamp. Documents are trees of nodes.
Ref
the address of one node within one document. A ref names a position, not an identity, so editing moves it.
Content hash
a digest of what a document says, taken over its rendering. Comparable between backends; see Content hash.
Backend
storage for documents — sqlite, a directory of org files, an Emacs session. See Store backends.
Service layer
the one place that knows what a create or an update means. See The service layer.
Adapter
a thin front end onto the service layer: the CLI, the HTTP API, the MCP tools.
Index
rows derived from a document — nodes, tags, properties, links, timestamps, full text. Always rebuildable; see The derived index.
Reindex
rebuilding those rows from the stored documents, after the extraction rules change.
Embedding
a vector standing for a node's meaning, used by semantic search.
Render method
how a document becomes other text — a Jinja2 template, or org-export. See Render methods.
Format
what that text is: html to begin with. It names the template, the exporter and the file extension.
Entry
one top level heading in a daily note — the unit org commit writes and org log reports.
Topic
an org-roam node, named by title, that org note files entries under. See Note topics.
Daily note
the org-roam file for one date. See Daily notes.
Daemon
the private Emacs the capture commands drive. See The Emacs daemon.
Canonical JSON
the schema-validated JSON shape both ingestion paths produce, modelled on ox-json's export.
ox-json
the Emacs exporter whose output shape the canonical model copies.
org-parser
the standalone tree-sitter parser used when there is no Emacs. See The org-parser adapter.
