org mcp

command user service

Speak MCP on stdin and stdout, so an agent can use the store without shelling out. 

uv sync --extra service

org mcp                # serve on stdio
org mcp --list-tools   # what an agent would see

Point an MCP client at the command: 

{"command": "orgface", "args": ["mcp"]}

The tools are generated

Each tool's name, arguments and result come from the corresponding HTTP operation's OpenAPI description, so adding a route adds a tool and the two cannot drift apart. Twelve tools come out: list_documents, read_document, read_document_text, summarise_document, create_document, replace_document, delete_document, read_node, update_node, delete_node, search and embed.

The MCP server calls the API in process, over an ASGI transport — no socket, no port, nothing else can reach it. Running org mcp does not expose anything on the network the way org serve does.

What an agent is told

The server carries instructions of its own: how a document is addressed, that a ref names a position and moves when the document is edited, that org's ID property is the identifier which survives editing, and that semantic search only finds what has been embedded. An agent that reuses a stale ref is the failure this is meant to prevent.
