The layering rule

concept developer

The rule, from CLAUDE.md and non-negotiable: *CLI and UI modules contain no data processing logic.* Commands parse arguments and call into data modules; ui.py renders what they return; every decision lives somewhere neither of them.

It is not aesthetic. It is what makes the HTTP API and the MCP tools possible without a second implementation: if a rule had been written inside a click command, every other front end would need its own copy, and the copies would diverge.

How to tell you are breaking it

  • A command module computing something it then prints.
  • A Jinja2 template reaching into the model to work out a headline's stars. Templates decide layout and nothing else.
  • A backend deciding what a ref means, or validating a document.
  • A rule about org — what counts as a tag, what a node's text is — living in a backend rather than beside the model.

Where things go instead

Argument shapes shared by commands
=commands/__init__.py=, declared once so commands stay consistent by construction.
Rendering for people
=ui.py=.
Decisions about documents
the service layer.
Decisions about org
beside the model — text.py, extract.py, refs.py, tree.py.
Decisions about storage
the backend.

DRY as it is meant here

As functionality is reused across commands, it is factored out rather than copied. The test that a factoring is right is usually whether a second adapter would have had to reimplement it: if so, it belongs lower down.
