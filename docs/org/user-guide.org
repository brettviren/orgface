For someone using orgface rather than changing it. Two orderings of
the same pages: read across the first to get the shape of the tool, then
down the second for whichever part you need.

* Quick start

#+begin_src sh
alias org=orgface

org commit -m "Fixed the thing" -m "Took all day."
org note -m "Fixed the thing" -m "Took all day."
org log --today
org visit yesterday
org daemon status

org store add notes.org
org store list
org search deadline --scope heading
#+end_src

* Reading order, breadth first

Each level of the subject before the level below it. Read the first tier
and you know what the tool does; read the second and you can run it.

* If something surprises you

- A command used a store you did not expect :: =org config show=, and see
  [[file:configuration.org][Configuration]] on which layer wins.
- A search found nothing :: check the backend can index at all —
  [[file:command-search.org][org search]] explains which can.
- A file came back reformatted :: [[file:backend-orgfs.org][The org file backend]] says what
  writing normalises, and [[file:roadmap.org][Roadmap]] what is known broken.
- Emacs was not touched :: only some commands need it;
  [[file:emacs-daemon.org][The Emacs daemon]] lists which.
