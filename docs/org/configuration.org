Every setting is declared once, in =SETTINGS= in =config.py=, with its
attribute name, its TOML section and key, its environment variable, its
default, and how to coerce it. Each layer reads that one declaration, so a
new setting is one entry rather than four edits.

* Layers

Layers apply in last-one-wins order:

: environment variables -> config file -> host file -> command line options

That the file beats the environment is deliberate: the file is the
considered choice and the environment is the ambient one. A command line
option beats both, and an option left unset does not count as a value, so
it cannot clobber a lower layer with =None=.

The file is named with =-c/--config=, or found at
=~/.config/orgface/config.toml= — see [[file:xdg-locations.org][XDG locations]].

* One directory, several machines

Beside the config file, a file named for the machine — its short host
name, as =hostname -s= prints it, plus =.toml= — is read after it and
overrides it. A directory synced between machines can therefore hold
=config.toml= with what they share and =<host>.toml= with what differs:

#+begin_src conf-toml
# config.toml
[store]
database = "~/sync/orgface/store.sqlite"

# haiku.toml
[daemon]
lifetime = "4h"
#+end_src

Either file may be absent. =ORGFACE_HOST= names the host file to use in
place of the host name. =org config show= lists the files it read, and
=org config paths= the host file it looks for.

* Embedding services

=[[embed]]= may repeat, one table per embedding service, listed in the
order to try them. A single =[embed]= table is a list of one, and with
none at all there is one service with the defaults below.

#+begin_src conf-toml
[[embed]]
url   = "http://127.0.0.1:8080"
model = "nomic-embed-text-v1.5"
identity = "nomic-embed-text"

[[embed]]
url   = "https://api.example.org/v1"
model = "nomic-embed-text"
api_key_passname = "example/api/key"
#+end_src

Both name one model, so they share an =identity= and the vectors either
makes. Listed together in the shared =config.toml=, each machine uses the
first that answers: where the local server runs, that one; elsewhere it is
refused quickly and the next is used. See [[file:semantic-search.org][Semantic search]].

The services are a whole, taken from the last layer naming any: a host
file with =[[embed]]= tables replaces the list rather than adding to it,
which is how one machine tries them in another order. The =ORGFACE_EMBED_*=
variables fill in what each service in a file leaves out — an API key
given that way goes to every service.

=batch= is how many texts go in one request (32 by default) and
=parallel= how many requests are in flight at once (1). Either may be more
than a service allows. A request that fails in a way suggesting so lowers
the number, logged as a warning, and embedding carries on with the lower
one: a busy answer (HTTP 429 or 503), or timeouts and dropped connections
while several requests are out, halve =parallel=; a refused batch (HTTP
413, or a 400, 422 or 500 that might be about size) halves =batch=, down to
one. A busy service with only one request out is waited for, honouring
=Retry-After=, up to five times. Setting them to what the service allows
avoids paying for the discovery on every run.

* The settings

#+begin_src conf-toml
[daemon]
server_name   = "orgface"  # ORGFACE_SERVER_NAME
lifetime      = "1h"              # ORGFACE_LIFETIME
emacs         = "emacs"           # ORGFACE_EMACS
emacsclient   = "emacsclient"     # ORGFACE_EMACSCLIENT
start_timeout = "120s"            # ORGFACE_START_TIMEOUT

[roam]
directory         = "~/org/roam"  # ORGFACE_ROAM_DIRECTORY
dailies_directory = "daily/"      # ORGFACE_DAILIES_DIRECTORY

[note]
topic = "Context Notes"           # ORGFACE_NOTE_TOPIC

[log]
pager = "less"                    # ORGFACE_PAGER

[[embed]]                              # may repeat; see below
url        = "http://127.0.0.1:8080"   # ORGFACE_EMBED_URL
model      = "nomic-embed-text-v1.5"   # ORGFACE_EMBED_MODEL
dimensions = 768                       # ORGFACE_EMBED_DIMENSIONS
# api_key  = "..."                     # ORGFACE_EMBED_API_KEY; prefer the env var
# api_key_passname = "embed/key"       # ORGFACE_EMBED_API_KEY_PASSNAME; first line of `pass embed/key`
# identity = "nomic-embed-text"        # ORGFACE_EMBED_IDENTITY; stored with vectors, defaults to model
batch      = 32                        # ORGFACE_EMBED_BATCH; texts per request
parallel   = 1                         # ORGFACE_EMBED_PARALLEL; requests at once

[store]
backend   = "sqlite"       # ORGFACE_STORE_BACKEND
database  = "~/.local/state/orgface/store.sqlite"
directory = "~/org"        # for the orgfs and emacs backends
#+end_src

An unknown section or key in the file is reported by name rather than
ignored, on the grounds that a typo in a config file is a question, not a
preference.

* Value spellings

- Durations :: =90s=, =30m=, =1h=, =1h30m=, =2 hours=, =1d=, a bare
  number of seconds, or =never= (=none=, =inf=, =0=) to disable expiry.
- Paths :: =~= and =$VARIABLES= are expanded.
- Booleans :: =1/true/yes/on= and =0/false/no/off=.

* Keeping the API key out of the file

Rather than writing =embed.api_key= into the config file, set
=embed.api_key_passname= to the name of a [[https://www.passwordstore.org/][pass]] entry. When no
=embed.api_key= is set, the first line printed by =pass <passname>= is
used as the key. It is read only when the embedding service is actually
contacted, so commands that never embed do not prompt for a passphrase.

* Seeing what is in effect

=org config show= prints the resolved value of every setting as a loadable
TOML file, optionally with its environment variable, and which file it came
from — the fastest
way to find out why a command is using a store you did not expect.
=org config init= writes a commented default file to the XDG location if
none is there yet. See
[[file:command-config.org][org config]].
